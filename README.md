# Bloomstudy

ヒントが花びらのようにひとつずつ浮かびあがるあいだに、答えを「思い出す」ゲーム型の学習ウェブアプリ。

- [要件定義書](Bloomstudy_要件定義書.md) — コンセプト・ビジネスモデル
- [機能要件書](Bloomstudy_機能要件書.md) — 画面一覧・機能要件
- [技術選定書](Bloomstudy_技術選定書.md) — 技術スタックと選定理由

## 実装上のメモ

### 漢字問題の生成

漢字ジャンルの問題は KANJIDIC2 · KRADFILE · JMdict から生成している。
**実行時に辞書APIを叩くのではなく、開発時に生成して JSON をコミットする。**

```bash
npm run dict:fetch                          # 初回のみ
npm run questions:kanji                     # 既定は小3〜小6 + 中学以上 → 1666問
npm run questions:kanji -- --grades=3,4     # 学年をしぼって確認する
npm run questions:kanji -- --report         # 書き出さず、内訳と先頭20問だけ確認
```

出力は `src/data/questions.kanji.generated.json`。直接編集しても次回生成で消える。
手で直したい問題は `src/data/questions.ts` の `MANUAL_QUESTIONS` に置く(同じ `answer` があれば生成側を捨てる)。

#### 出題文もヒントも熟語で出す

出題は**熟語の穴うめ**。対象の字を `◯` で伏せた熟語と、その読みを出す。

```
出題  「◯営」うんえい          ← こたえは 運(1字)
ヒント 熟語「◯河」うんが / 熟語「◯休」うんきゅう / 訓読み はこぶ
```

読みだけを出す形(`運 → はこぶ`)にしていたときは、「あつい」→ 熱/暑/厚 のように
**出題文から答えが一意に決まらない字を丸ごと落とすしかなかった**。
熟語に読みを添えれば字は一意に決まるので、訓読みを持たない字も出せる(378問 → 767問)。

出題文とヒントは同じ井戸から汲む。その字を含む熟語を最大4語えらび、
先頭(いちばん短い語)を出題文に、残りをヒントに回す。

**部首・パーツ・画数は出さない。** 字形の手がかりを渡さないため。
部品を答えさせる assemble モードでは、部首やパーツのヒントが答えそのものになってしまう。
熟語なら意味と読みだけを渡せるので、**こたえかたごとにヒントを切り替える必要が無い**。

熟語が足りない字だけ、訓読み・音読み・画数で補う(`MIN_HINTS` を満たすまで)。
同系語が並ばないよう、既に採った語を含む語は飛ばす(`委員` を採ったら `委員会` は使わない)。

出題文に使う熟語には、ヒントより厳しい条件を掛けている。

| 条件 | 理由 |
|---|---|
| 伏せた形と読みで漢字が1字に決まる | `「◯行」かんこう` は 刊行 / 慣行 のどちらでも成り立ってしまう |
| 対象の字がその語に1回しか出ない | 2回出ると `「◯◯」` になって手がかりが残らない |

熟語に混ぜる字(伏せていない側)は**常用漢字だけ**にする。出題文にもヒントにも
そのまま出るので、読めない字が混じると手がかりにならない(`愛 → 「◯嬌」あいきょう`)。

ヒントの見出しに答えの字が入る場合(`訓 → 訓読み`、`熟 → 熟語`)は見出しを落とす。
ラベルが答えそのものを見せてしまうため。

#### assemble モード用のパーツ

KRADFILE の分解から、正解パーツと部品タイル(正解 + ダミー)を生成する。

ダミーは**見分けにくい部品**を優先する(`辶` に対して `廴` `走`)。
形が違いすぎる部品を混ぜると、思い出さなくても消去法で解けてしまう。
機械的に「似ている」を判定する手段が無いため、`scripts/kanji-radicals.ts` の
`CONFUSABLE_GROUPS` に35組を手で持っている。足りない分は同じ画数の常用部品で埋める。

**ダミーが簡単すぎると気づいたら、この表に足すこと。**

##### 2部品を1つのマスに組む

assemble は**2部品に割れる字**だけを出し、部品を1つのマスの2枠へスライド
(タップでも可)して組ませる。割れる向きは字ごとに決まっていて2通りある。

| 向き | 枠 | 例 |
|---|---|---|
| `horizontal`(左右 ⿰) | へん / つくり | `位` = `亻` + `立` |
| `vertical`(上下 ⿱) | うえ / した | `意` = `音` + `心` |

どちらに置いたかまで正誤に含めるので、入れ替えると不正解になる。

KRADFILE は部品を持つが**配置(左右・上下)は持たない**(`亻`+`立` が左右の `位` なのか、
`化`+`貝` が上下の `貨` なのかは分からない)。そのため、割れる向きと**先にくる部品**を
`src/features/assemble/index.ts` の `LEFT_PART_OF`(左)と `TOP_PART_OF`(上)に手で持つ。
もう一方は残りの部品なので表には持たない。収録は「2部品がそのまま字形になる」字に絞る
(`移` は `禾`+`多` だが KRADFILE では `禾`+`夕` になり字形と合わないので入れない)。
たれ(`广`・`厂`・`尸`)やにょう(`辶`)、囲む字(`囗`)は2枠に収まらないので入れない。

**字を足したいときは `LEFT_PART_OF` / `TOP_PART_OF` に `答えの字: 先の部品` を追記する。**
その字に `parts`(2部品)と `partTiles` があれば、そのまま assemble に出る。

#### 除外の条件

生成側は「作れないものは書かない」方針で、次に当てはまる字は問題にしない。
`--report` の除外内訳で数が見える。

| 除外 | 理由 |
|---|---|
| 出題文にできる熟語が無い | 伏せると別の字でも成り立つ語しか無い、または常用漢字だけの熟語が無い |
| ヒントが3個未満 | 熟語も訓読みも音読みも画数も足りない字 |
| KRADFILEに分解が無い | 部品タイルを作れない |

パーツは 2〜4個に割れて、かつ筆画レベルまで降りていない字だけに付ける
(`悪` → `｜`/`一`/`口` は `亜` を指せていない)。付かない字は assemble モードでは出題されない。
付いていても、assemble に出るのは2部品でかつ前述の表に収録した字だけ。

`hintSource` は `見出し|本文` 形式(`熟語|「◯営」うんえい`)。
出せるヒントの種類は字ごとに変わるので、見出しは並び順ではなくデータ側が持つ。
見出しを落とした行(`おしえる`)は本文だけとして扱う。

出題文の読みは `prompt` とは別に `promptReading` に持つ。画面では出題語より小さく置く。

### 英単語問題の生成

JMdict(common語のみ)と NGSL から生成する。漢字と同じく開発時に生成して JSON をコミットする。

```bash
npm run questions:english                  # 既定 → 1709問
npm run questions:english -- --bands=1000  # NGSL上位1000語の範囲だけ
npm run questions:english -- --report      # 書き出さず、内訳と無作為20問だけ確認
```

出力は `src/data/questions.english.generated.json`。
出題語は漢字表記(`uk` タグの語はかな表記)、答えは第一訳、同じ語義の別訳は
`acceptableAnswers` に入れて正解扱いにする。

**答えの難易度は NGSL(学習者向け基本語2801語)で制御している。** これが無いと
militarism・lipstick のような優先度の低い語まで問題になる。
頻度で訳語を選び直すと訳が壊れる(顔ぶれ → members)ため、
**第一訳をそのまま答えにして、それが NGSL に無ければ問題ごと捨てる**方針にしている。

| 除外 | 理由 |
|---|---|
| 1語の英単語にならない | 複数語の訳(to live on など)は判定にも1文字ずつのヒントにも向かない |
| 答えがNGSLに無い | 学習の優先度が低い |
| カタカナ語 | 出題語が答えそのものになる(テーブル → table) |
| 答えが他の問題と重複 | 同じ答えの問題を作らない |
| 答えが4〜10文字の外 | 短いとヒントが2段階しか作れず、長いと開放しきらない |
| 学習に出すのに向かない語 | 下記「不適切な語の除外」を参照 |

JMdict のタグでは弾けない問題(`おなら` → wind など)は
`scripts/english-denylist.ts` に出題語を書いて除外する。
生成JSONを直接編集しても次回生成で消える。

### 不適切な語の除外

**辞書をそのまま流すと、性的・排泄・死や暴力に関する語が出題やヒントに混ざる。**
小学校配当の漢字を扱うアプリなので、生成の段階で落とす。

判定は `scripts/unsuitable.ts` に集約してあり、漢字・英単語の両方の生成が使う。

**JMdict のタグでは弾けない。** `射精` `精液` は俗語でも古語でもなく医学用語として
登録されているため、`vulg` も `sens` も付かない。英語の語義に現れる語で見分けるのが、
いまのところ唯一の機械的な方法。

**判定は必ず第一語義(その語の主要な意味)だけに掛けること。** 全語義を見ると、
二次的な意味を持つだけの普通の語まで落ちる。

```
関係 → relation …(後の語義に sexual relations)   残す
国際 → international …(diplomatic intercourse)  残す
営み → activity …(execution)                    残す
射精 → ejaculation(第一語義そのもの)              除外
```

語義に手がかりが出ない語(`遺体` は第一訳が body)は、denylist で個別に落とす。

| ファイル | 用途 |
|---|---|
| `scripts/unsuitable.ts` | 語義から機械的に判定する語のリスト |
| `scripts/jukugo-denylist.ts` | 漢字ヒントの熟語を個別に除外 |
| `scripts/english-denylist.ts` | 英単語の出題語を個別に除外 |

**同種の語を見つけたら、1件ずつ生成JSONから消すのではなく、上のどれかに足すこと。**
生成JSONを直接編集しても次回生成で戻る。

なお `death` `kill` `murder` `suicide` など、性的でない語も同じリストで落としている。
過剰だと感じたら `unsuitable.ts` の `TERMS` から外せる。

### ジャンルを追加するとき

ヒントの出しかたはジャンルごとに個別設計する方針のため、共通ロジックには寄せない。

1. `src/types/index.ts` の `GenreId` に ID を追加
2. `src/features/hints/<genre>.ts` にヒント分解ルールを実装し、`src/features/hints/index.ts` の `HINT_RULES` に登録
   (`layout` に `inline`(横に連ねる) か `stacked`(行を積む) を指定する)
3. `src/data/genres.ts` にジャンルと `inputModes` を追加
4. 問題は `src/data/questions.ts` に手で書くか、`scripts/` に生成スクリプトを足す
5. `src/components/ActivityArt.tsx` に一覧用の絵を足す(後述。`ActivityId` 全部に要るので、
   足さないと型エラーで気づく)

そのジャンルで新しいこたえかたが要るなら、`InputMode` に足したうえで
`InputModeSheet` のラベル・`QuizPage` の分岐・`quizSource` の `isAnswerable` を揃えること。

### 一覧のカード(動く絵)

ジャンル選択の一覧は、左に**中身を小さくして流す絵**、右に名前と説明を置く
([src/components/ActivityArt.tsx](src/components/ActivityArt.tsx))。

```
┌──────────────────────────────┐
│ ┌────┐  かたちを なぞろう      │   絵 = 正方形
│ │ ◯↷ │  まる・さんかく・…      │   こども 96px / おとな 72px
│ └────┘                        │
└──────────────────────────────┘
```

名前と説明だけの四角が並んでいても、**字を読めない子には何が始まるのか分からない**。
中身をそのまま小さくして流しておけば、読まずに選べる。

| 一覧のもの | 絵の中身 |
|---|---|
| 英単語 | 「りんご」の下でヒントが1つずつ灯り、最後に `apple` が浮かぶ |
| 漢字 | `◯ 校` の ◯ に `学` が入る |
| かたちを なぞろう | うすいお手本のまるを、指が追って緑の線になる |
| ひらがなを なぞろう | 同じく「い」を2画で |
| かんじを なぞろう | 同じく「山」を3画で |
| かんじを くみたてよう | `日` と `月` がマスに入り、`明` になる |
| ちがい さがし | お手本と、すこしだけ形の違う3つ。同じものにしるしが付く |

**動画ではなくSVGにしてある。** 数KBで読み込み待ちが無く、どの大きさでも粗くならず、
「動きを減らす」設定のときは完成形で止められる。動きはSVG内のSMILで完結させ
(ロゴ・挿絵と同じ作法)、止める判断だけ `prefersReducedMotion()` で行う。

- **絵は本編と同じ材料で描く。** なぞりがきの線づかい(太さ10・うすいお手本・緑の線)は
  `TraceCanvas` と、ちがいさがしの図形は `features/match` の `figurePath` と揃えてある。
  絵とやることが食い違わないようにするため
- **なぞりがきの見本だけは出題データから引かず、代表の1つを写して持つ。**
  カードの絵は毎回おなじ形が出たほうが分かりやすい。
  パスの長さ(`length`)は線を1本ずつ引くのに要るので、**形を差し替えたら測り直すこと**
- **1周の長さは絵ごとに変えてある**(4.0〜5.2秒)。手数に合わせるのと、
  一覧に5つ並んだときに全部が同じ拍で動くと、表示が切り替わる機械のように見えるため
- **線を引き直す瞬間は、消えている間に隠す。** 描き終わり→フェードアウト→(この間に戻す)
  →次の周、の順にしてある。いきなり線が消えると目に付く

### ロゴと配色

ロゴアセットは `public/` に置いてある。

| ファイル | 用途 |
|---|---|
| `public/bloomstudy_icon.svg` | 縦組みロゴ・アニメーション版。オープニング演出で使用 |
| `public/bloomstudy_logo.svg` | 横組みロゴ・アニメーション版 |
| `public/bloomstudy_icon_static.svg` | 縦組みロゴ・静止版(アニメーションを外しただけ) |
| `public/bloomstudy_logo_static.svg` | 横組みロゴ・静止版。ヘッダーで使用。ヘッダーに収まるよう、図形の座標はそのままに viewBox をコンテンツの実測値に合わせて詰めてある |
| `public/favicon.svg` | 花びらモチーフを正方形に切り出した静止版。ファビコン専用 |
| `public/bloomstudy_hero.svg` | トップの挿絵・アニメーション版。花が回り、ペンが `Bloomstudy` を1文字ずつ書き上げる11秒ループ |
| `public/bloomstudy_hero_static.svg` | トップの挿絵・静止版(書き上がった状態。ペンなし) |

**ロゴアセットを使うのはおとな向けだけ。** こども向けは `Bloomstudy` のワードマークを出さず、
顔つきのマークだけにする(後述)。

`BloomLogo` が `variant`(縦組み / 横組み)と `animated`(既定 false)でロゴ4ファイルを出し分ける。
挿絵は `HeroVisual` が担当し、`prefers-reduced-motion: reduce` のときだけ静止版に差し替える。
パスの定義はどちらも `src/assets/logos.ts` に集約している。

ロゴ単体ファイルのアニメーションはSVG内のSMILで完結しているため `<img>` で読み込む。
アニメーションは `repeatCount="1"` + `fill="freeze"` で**1回だけ再生して完成形で止まる**。
ループさせると2.4秒ごとにロゴが消えて出直すうえ、静止画としてラスタライズされる場面
(ファビコン・OGP画像など)で `opacity:0` の途中フレームが出てしまうため、
ファビコンにはアニメーションを含まない `favicon.svg` を使っている。

トップの挿絵だけは例外で、`repeatCount="indefinite"` のループにしてある。
書き上がりを2.4秒見せてから文字を消して書き直す構成で、尺は `dur="11s"` に揃えてある
(各要素の `keyTimes` は 11 秒を 1 とした比率で並んでいるので、
尺を変えるときはファイル内の `dur` をまとめて書き換えること)。

#### 顔つきの花マーク(こども向け)

画面の中の花マーク(`BloomMark`)は、`face` を渡すと**顔つき**になる。
渡さなければ今までどおり花びらだけで、**おとな向けの画面では渡さない**。

| `face` | 見た目 | 出す場面 |
|---|---|---|
| `smile` | ひらいた目 + 小さい笑み | ふつう・待っているとき(トライアル終了) |
| `joy` | 閉じた目(^ ^)+ 開いた口 + ほお | できたとき(正解・ぜんぶできた) |
| `sleepy` | 閉じた目 + 小さい口 | よみこみ中(`motion="loop"` と組ませる) |

```tsx
<BloomMark size={120} face="joy" />                        {/* こども向け専用の画面 */}
<BloomMark size={100} face={isKids ? 'joy' : undefined} /> {/* 共通の画面 */}
```

なぞりがき・ちがいさがしは**こども向け専用の画面**なので、そのまま `face` を渡している。
結果・ローディング・トライアル終了はおとなと共通なので、`useAudienceMode() === 'kids'`
で出し分ける。

- **顔は中心の円を大きくして描く。** 元の中心(`r=4.5`)では顔が入らないため `r=8` に広げ、
  花びらの座標と外形はそのままにしてある。花びらが顔の後ろから出ているように見え、
  マークの大きさはおとな向けと揃う
- **顔の色だけは CSS 変数(`var(--color-bloom-700)` など)で描く。** こども向けでは
  地がクリームに入れ替わる(後述)ので、花びらと同じようにハードコードすると地から浮く
- 顔は `[data-bloom-part="center"]` にまとめてあるので、**中心と同じ間で開く**
- 進み具合を出す小さい花(`size={20}`)には顔を付けていない。この大きさでは目と口が潰れる

**顔つきは止まっていない。** 花ごとゆっくり左右に傾き、ひらいた目はときどきまばたきする。

| `motion` | 動き |
|---|---|
| `bloom`(既定) | 1回開く → **開き終わったら、そのまま揺れ続ける**(顔つきのときだけ) |
| `idle` | 開く動きを出さず、開いた形のまま揺れ続ける。ずっと出ている場所(ヘッダー)用 |
| `loop` | 花びらの開閉をくり返す(ローディング)。揺れは足さない |
| `none` | 完全に静止 |

- **傾きは5度・3.6秒の往復まで。** 大きく振ると、ヒントや問題より先に目が行ってしまう
- **まばたきは `smile` だけ。** 目をひらいている顔にしか出せない。
  周期は 5.2 秒で、閉じているのはそのうち 0.2 秒ほど(`[data-bloom-eyes]` を縦に潰す)
- 揺れは花びらと顔をまとめた `[data-bloom-sway]` を回す。花びらは自分の回転を持っているので、
  まとめて回す入れ物を1枚はさんである
- **開いている最中は揺らさない。** どこで開き終わったのか分からなくなるため、
  `bloom` は全部の花びらが開き終わってから揺れに入る
- `prefers-reduced-motion: reduce` のときは、開く動きも揺れもまばたきも出ない(顔はそのまま出る)

**こども向けはロゴもこのマークだけにする。** 字を読めない年齢を想定しているので、
読めないワードマークを出しても目印にならない。出しているのは2か所。

| 場所 | おとな | こども |
|---|---|---|
| ヘッダー([AppHeader](src/components/AppHeader.tsx) の `HeaderMark`) | 横組みロゴ(h-9=36px) | `face="smile"` のマーク(44px・`motion="idle"`) |
| オープニング([OpeningSplash](src/components/OpeningSplash.tsx)) | 縦組みロゴ(SMILで1回再生) | `face="smile"` のマークが開く |

- ヘッダーのマークは**文字が無いぶん小さく見える**ので 44px にしてある。
  トップへ戻る押し場所でもあり、他の押し場所(`min-h-11`)と同じ大きさに揃うため
- オープニングの尺(`LOGO_MOTION_MS`)はモードで分けていない。こども向けのマークは
  最後の花びらが開き終わるのが約1.1秒で、ロゴの 1.3 秒に収まる
- こども向けは読み込むロゴファイルが無いので、オープニングの先読み(`fetch`)も飛ばす
- ヘッダーは `motion="idle"`。遷移のたびに開き直さず、開いた形のまま揺れ続ける

ロゴアセット(`public/`)とファビコンには顔つき版が無い。**画面の中で描くマークだけ**を
差し替えていて、ファビコン・OGPは おとな / こども で変えていない。

### おとな向け / こども向け

**トップだけをモードごとに分ける。** `/` がおとな向け([TopPage](src/pages/TopPage.tsx))、
`/kids` がこども向け([KidsTopPage](src/pages/KidsTopPage.tsx))。
言葉づかいや文字の大きさを別々に決められて、その先(ジャンル選択・出題・結果)は
同じ画面を使えるため。画面を丸ごと2組に分けると、直しが常に2か所になる。

```
/         おとな向けトップ ┐
                          ├→ /genres → /quiz/:genreId → /result  (共通)
/kids     こども向けトップ ┘
```

切り替えはヘッダー右の2つのボタン(`AudienceSwitch`)。押すと**そのモードのトップへ移る**。
途中の画面から中身だけ入れ替えると、モードで出すジャンルが変わったときに
どこに居るのか分からなくなるため、行き先はトップに固定している。

**出題中(`exitTo` あり)は切り替えを出さない。** 切り替えるとトップへ移るので、
離脱を止めている画面に抜け道を作ってしまう。

選んだモードは `localStorage`(`src/services/audienceMode.ts`)に残す。
次にアプリを開いたときは前に使っていた側から始まる(`/` を開くと、
こども向けを使っていれば `/kids` へ送る)。切り替えは**押した時点で保存**してから
移動するので、こども向けから「おとな」を押しても送り返されない。

ロゴは横長(300:62)で、切り替えと並べると 320px 幅の端末で収まらない。
`min-w-0` で縮めるのを許し、`object-contain` で縦横比を保ったまま小さくする
(360px では 174px のまま、320px で 150px に縮む)。

**こども向けのジャンルはまだ無い。** 足すときは、画面ではなくジャンル側を
`useAudienceMode()` で出し分ける。

#### 言葉はモードごとに1か所へ集める

画面に出す文字列は [src/data/copy.ts](src/data/copy.ts) が持ち、画面は `useCopy()` で受け取る。

```
copy.genreSelect.title   おとな「ジャンルをえらぶ」 / こども「なにを べんきょう する？」
copy.hints.next(9)       おとな「つぎのヒントまで 9 秒」 / こども「つぎの ヒントまで 9 びょう」
copy.parts.recalled      おとな「思い出した」 / こども「おもいだした」
```

こども向けは**漢字を減らし、文を短く、話しかける調子**にする。
画面側に文字列を置かないのは、言い回しを直すときに全画面を触らせないため。

これに合わせて、**ジャンルの「構造」と「言葉」を分けた**。
`Genre`(data/genres.ts)はこたえかた・ガイド・読み上げだけを持ち、
ラベル・説明・出題語の見出しは `copy.genres[genreId]` にある。難易度も同じで、
並び順は `DIFFICULTY_ORDER`(types)、見出しと対象のめやすは copy が持つ。

読み上げ用のラベル(`aria-label`)は共通のままにしている。目に見える言葉ではないので、
モードで言い換えても得がない。

### なんいどは「だれ向けか」で切る

やさしい/ふつう/むずかしい をやめ、**対象者**で6段階にしてある。
何を根拠に割り当てるかはジャンルで違う。

| なんいど | 漢字 | 問題数 | 英単語 |
|---|---|---|---|
| 小学1・2年 | 配当学年 1〜2(240字) | なぞり240 / くみたて36 | — |
| 小学3・4年 | 配当学年 3〜4 | 388 | — |
| 小学5・6年 | 配当学年 5〜6 | 376 | — |
| 中学生 | 中学以上のうち**よく見る**字 | 324 | NGSL 上位1000語 671 |
| 高校生 | 同 中くらい | 297 | 〜2000語 623 |
| 社会人 | 同 あまり見ない | 281 | 〜3000語 415 |

**中学以上を学年で割らないのは、国が決めていないから。** 学年別漢字配当表があるのは
小学校だけで、中学校の学習指導要領は「どの字を何年で習うか」を決めていない
(教科書ごとに順番が違う)。代わりに KANJIDIC2 の出現頻度順位を実データから3等分する。
決め打ちの順位にしないのは、辞書が更新されたときに偏らせないため。

**英単語に小学生向けが無いのは、対応づけられるデータが無いから。** 学習指導要領は
語数(小学校で600〜700語程度)しか決めておらず、語彙リストを持たない。
NGSL の頻度帯(1000/2000/3000)しか手元に無いので、3段階にとどめる。

#### 熟語の相手は、その学年までに習う字に限る

出題文は「◯営」のように**伏せていない側の字がそのまま出る**。相手が上の学年の字だと、
その学年の子には出題文が読めない。

```
直す前  一(小1) → 「◯位」いちい      位は小4
        歌(小2) → 「演◯」えんか      演は小5
```

`partnerGradeCap()`(scripts/difficulty.ts)で、小3・4なら小4まで、小5・6なら小6まで、
中学以上は常用漢字すべて、と上限を掛けている。熟語の候補は減るが、
小6までに限っても2語以上持つ字は993字あるので足りる。

#### 色はトークンだけ差し替える

こども向けは、白い紙のような地を**あたたかいクリーム**に置き換え、緑の黒みを抜き、
文字を真っ黒でなく茶みのある濃灰にする。

やり方は [src/index.css](src/index.css) の `:root[data-audience='kids']` で
**色トークンの値だけ**を上書きする形。Tailwind v4 のユーティリティは
`var(--color-*)` を参照するので、`<html data-audience="kids">` が付くだけで
全画面の色が入れ替わる。画面側のクラス(`bg-bloom-700` など)は1つも触っていない。

属性は2か所で貼る。`main.tsx` が**最初の描画より前**に(色のちらつき防止)、
`App` の `AudienceTheme` が切り替えのたびに追従する。

**やさしい色にしても、コントラストは落とさない。** 読めない色はやさしくないので、
本文 4.5:1 / 小さい字 3:1 を満たす値だけを採った(実測)。

| 組み合わせ | おとな | こども | 必要 |
|---|---|---|---|
| 本文 `ink-600` / 地 | 6.36 | 5.45 | 4.5 |
| 小さい字 `ink-400` / 地 | 3.09 | 3.15 | 3.0 |
| 見出し `ink-900` / 地 | 14.44 | 10.84 | 4.5 |
| 白 / 主ボタン `bloom-700` | 6.20 | 5.20 | 4.5 |
| `bloom-100` / `bloom-700` | 5.33 | 4.55 | 4.5 |

狭いタイルの見出しには `break-keep` を掛ける。日本語は既定でどこでも折り返すため、
掛けないと「いま れんぞ / く」のように語の途中で切れる。

### こども向けのあそび

**こども向けは、字を書けない・読めない年齢を想定している。** 熟語の穴うめは出せないので、
こどもモードの一覧にはクイズのジャンルを並べず、あそびだけを出す
([src/data/activities.ts](src/data/activities.ts))。

```
一般            こども
・英単語        ・かたちを なぞろう
・漢字          ・ひらがなを なぞろう
                ・ちがい さがし
```

**漢字のなぞり・くみたては、こども向けの一覧には並べない。**
一般向けの漢字で「小学1・2年」を選ぶと、こたえかたとして同じ画面へ入るため
(`/trace/kanji` と `/build`)。一覧に出さないだけで id・文言・絵は残してあるので、
こども側にも並べたくなったら `ACTIVITIES` に1行足せば戻る。

一覧に並ぶものは `Activity` にまとめてある。クイズは `genreId` を持ち、
選ぶとこたえかた・なんいどのシートを開く。あそびは `path` を持ち、押したらすぐ始まる
(小さい子ほど、始めるまでの手数は少ないほうがいい)。

#### なぞりがき

グレーのお手本を指で追うと、追えたところまでが緑になる。1画ずつ、書き順どおりに進む。

```
      ┌─────────┐
      │    ●\    │   ● = ここに指を置く(光っている)
      │      \   │
      │      /   │   なぞれたところが緑になる
      │     /    │
      └─────────┘
```

**正誤を出さない。** 間違いで止めたり、やり直させたりもしない。
なぞれたら次、それだけ。1回5問で必ず「ぜんぶ できた!」に届かせる。
終わりの見えない出題は、この年齢では達成感にならない。

判定は、お手本のパスを 2 ずつの点に刻んで指との距離で見る
([src/components/TraceCanvas.tsx](src/components/TraceCanvas.tsx))。

| ルール | 値 | 理由 |
|---|---|---|
| 線から離れてよい距離 | 14 | 線幅(10)より広い。狙って線に乗せられる年齢ではない |
| 一度に進める点数 | 12 | 終点だけ触ってごまかせないようにする上限 |
| 進む先 | 指にいちばん近い点 | 「届いている中でいちばん先」だと指より先に緑が伸びる |
| 書き始め | すでになぞった側だけ | 途中で指を離しても、最初から引き直せる。先へは飛べない |

最後のルールは実機で見つけた。始点だけを受け付ける作りだと、
途中で指を離した子が線の最初から引き直しても**何も起きない**。

漢字は**小1・小2の240字だけ**をなぞらせる。この学年はまだ熟語の穴うめが成立しない
(出題文に出る相手の字が読めない)ので、クイズではなくお手本を出す。
小3以上は熟語の穴うめのクイズへ渡す。

#### お手本は KanjiVG から生成する

フォントの字形からは書き順を復元できない。KanjiVG は字形を
**書き順どおりに並んだストロークの SVG パス**で持っているので、これを使う。

```bash
npm run dict:fetch   # 初回のみ(KanjiVG も一緒に落ちる)
npm run strokes      # ひらがな46字 + 小1・小2の漢字240字
                     # → strokes.hiragana.generated.json(16KB) / strokes.kanji.generated.json(152KB)
```

座標は小数1桁に丸めて書き出す。KanjiVG は小数2桁で持っているが、109四方の中で
0.05 の違いは見えないのに、漢字240字ぶんでは容量に効く(180KB → 152KB)。

座標系は KanjiVG の 109×109 の正方形。図形のお手本([src/features/trace](src/features/trace/index.ts))も
同じ座標系で手で書いてあるので、字と図形を同じ仕組みで扱える。

なぞる順は画数の少ない字から。生成データは五十音順・学年順なので、読み込み側で並べ替える。

**KanjiVG は CC BY-SA 3.0**(他のデータは 4.0)。表示物に出典の掲示が要る。

#### かんじの くみたて

小1・小2の漢字を、お手本を覚えてから部品で組み立てる。
**操作も判定も組み上がりの演出も、おとな向けの「パーツを組む」と同じ `PartsInput`** を
そのまま使う。違うのは、出題が熟語ではなくお手本の字そのものであることだけ。

```
この かんじを よく みてね        [おもいだした] を押すと
        兄          →          お手本が消えて、タイルが出る
```

お手本を出したまま組ませると写すだけになるので、覚えたら引っこめる
(`PartsInput` の `onReveal` で外へ知らせる)。**間違えても止めない。**
正しい字を見せてから次へ進む。やり直させはしない。

出せるのは**36字**。240字のうち2つの部品に割れるのは62字で、そこから
KRADFILE の分解が字形と合わない字(花を 亻+艹 と出す、海を 氵+乞 と出す)と、
にょう・かまえ(近・間・図)を外した数。

```bash
npm run parts:kanji              # 小1・小2の部品データ → src/data/parts.kanji.generated.json
npm run parts:kanji -- --report  # 書き出さず、割れる字だけ確認
```

どちらが左(上)かは KRADFILE に無いので、`src/features/assemble` の表に手で持つ
(`LOW_LEFT_PART_OF` / `LOW_TOP_PART_OF`)。**字を足すときはここに1行足す。**
表に無い字は一覧に出ないだけで、壊れはしない。

#### ちがい さがし

お手本と同じ図形を4つから選ぶ。**4つとも同じ色・同じ向き・同じ種類の形**で、
違うのは形のこまかいところだけ(ほしの角が5つか6つか、しかくの角がどれだけ丸いか)。

```
star-corners      ✦ ★ ✶ ✷ ✸     かどの数 4〜10
star-sharpness    ★ ★ ★ ★       とがりぐあい(へこみの深さ)
polygon           ⬠ ⬡ ⯃ ⯄       かどの数 5〜10
square-roundness  ■ ▢ ▢ ●       かどの丸み 0〜30
circle-height     ● ⬭ ⬭ ⬭       たて横の比 1.00〜1.35
flower-petals     ✿ ❀ ❁ ❋       はなびらの数 4〜9
```

**形はパスを手で書かず、数から組み立てる**([src/features/match](src/features/match/index.ts))。
角の数や丸みを数で持てば「隣どうしがいちばん似ている」並びが作れて、
**ダミーを答えからどれだけ離すか**で難しさを決められる。

| 問 | ダミーの取りかた |
|---|---|
| 1–2 | 答えからいちばん遠い3つ(違いが大きい) |
| 3 | まん中の3つ |
| 4–5 | 答えのすぐ隣の3つ(いちばん見分けにくい) |

色と向きは4つとも同じなので、**色の見え方に関係なく解ける**。
難しさは形の違いだけで作っていて、色は問題ごとの彩りにしか使っていない。

**はずしても止めない。** ×も減点も出さず、押したタイルが揺れて戻るだけ。
2回続けてはずしたら正解を光らせる。解けずに終わらせないことを優先する。

タイルは `aria-label`(「あかい かどが 5この ほし」)を持つ本物のボタンにしてある。
図形は読み上げられないので支援技術にはこれが要る。**変種ごとに言い分ける**ので、
隣どうしの変種でもラベルは必ず違う。あとで音声モードを足すときの下地でもある。

生成したものは点検してから使うこと。楕円の縦幅を上限で頭打ちにしていたときは、
いちばん縦長の2つが**同じ形**になり、選択肢に同じものが2つ並んでいた
(15000問の点検で発見。見た目・ラベル・色・形の種類が想定どおりかを見ている)。

#### これから足すあそび

- **パイプでボール** — 配管をつないでボールを通す
- **音声モード** — ちがいさがしを、読み上げだけで遊べるようにする。
  自前で読み上げると支援技術と二重に喋るため、まずタイルのラベルを正しく持たせてある

### 画面ごとに分けて読む

**出題データとお手本データが重い**(漢字の問題で約100KB、なぞりのストロークで約170KB)。
その画面に入るまで読まないよう、データを抱える画面は `lazy()` で分ける
([src/App.tsx](src/App.tsx))。トップとジャンル選択は最初に必ず通るので同梱する。

```
最初に読む   258KB (gzip 82KB)   トップ・ジャンル選択・共通UI
出題         21KB + 問題データ
なぞり       145KB (gzip 55KB)   ストローク
ちがいさがし  6KB
```

分ける前は1本で854KB(gzip 232KB)だった。待っている間は `Loading` を出すが、
`Loading` 自体が 200ms は何も描かないので、手元で開くぶんにはチラつかない。

### ヘッダーとオープニング演出

- `AppHeader` を `AppShell` に組み込んであるので、全画面のヘッダー左にロゴが出る。ロゴはトップへのリンク。右側は今後のナビゲーション用に空けてある
- **ロゴの中身はモードで変わる。** おとな向けは横組みロゴ(静止版)、こども向けは顔つきのマークだけ(前述)
- **ヘッダー右におとな/こどもの切り替えを置く。** 押すとそのモードのトップへ移る(後述)
- **出題中だけはロゴから飛ばさない。** `AppShell` に `exitTo` を渡すとロゴのリンクが外れ、代わりに左上へ「← やめる」が出る。押すと「とちゅうで やめる?」の確認をはさんでから離れる。ヒントを見ているあいだにロゴを押してしまい、問題ごと消えるのを止めるため
- `OpeningSplash` がトップ画面を開いたときに縦組みロゴを全画面で1回再生し、フェードアウトして本編に渡す(こども向けは顔つきのマークだけが開く)
- 再生は**1セッションにつき1回**。判定は `src/services/openingSession.ts`(`sessionStorage`)。他画面から戻ってきても再生しない
- `prefers-reduced-motion: reduce` のときは演出をスキップする

演出の尺は `OpeningSplash.tsx` の定数で調整する。

| 定数 | 既定 | 意味 |
|---|---|---|
| `LEAD_IN_MS` | 600ms | ロゴを出してから花が開き始めるまでの間 |
| `LOGO_MOTION_MS` | 1300ms | SVG側の動きが完成形に達するまで(`dur="2.4s"` × 文字が出そろう `keyTimes` 0.5417) |
| `HOLD_MS` | 500ms | 完成したロゴを見せておく時間 |
| `FADE_MS` | 400ms | フェードアウト |
| `MAX_WAIT_MS` | 4000ms | 読み込みが返ってこなくても本編に進む上限 |

ロゴの下には `LoadingDots`(3点が順に跳ねるマーク)を出す。これは飾りではなく、
**演出の尺と実際の読み込み(`document.fonts.ready`)の両方が終わるまで**スプラッシュが閉じない。
フォントが遅い回線では演出が終わってもドットが回り続け、揃った時点でフェードアウトする。
ロゴが出た瞬間にドットが下へずれないよう、ロゴの領域は `aspect-[400/360]` で最初から確保している。

`<img>` はDOMに挿入された時点でSMILが動き出すため、**lead-in のあいだは `<img>` をマウントしない**。
同じ理由で、先読みは `<img>` ではなく `fetch()` で行っている(画像として先読みすると時計が先に動く)。
`LOGO_MOTION_MS` はSVG側の `dur` に依存しているので、**SVGの尺を変えたらこちらも合わせること**。

### ローディング表示

ローディング表示は2種類ある。用途で使い分ける。

| コンポーネント | 見た目 | 用途 |
|---|---|---|
| `Loading` | 花びらが開閉 + 文言 | 画面の中身を待つとき(マイページ、出題画面など) |
| `LoadingDots` | 3点のドット | 花のモチーフと重ねたくない場所。オープニングのロゴ下 |

`Loading` が花びらの開閉アニメーション(`BloomMark motion="loop"`)と文言を出す。

- `delayMs`(既定 200ms)を過ぎるまで何も描かないので、一瞬で終わる読み込みではチラつかない
- こども向けのときだけ、花が目を閉じた顔(`face="sleepy"`)になる(前述)
- 数秒以上かかる処理では `hint` に待ち時間の見込みを添える。機能要件書3章の通り、
  レベル4(Transformers.js)の初回モデル読み込みを入れるときは必ず明示すること

```tsx
<Loading />
<Loading message="記録をよみこみ中" />
<Loading message="判定の準備をしています" hint="初回だけ十数秒かかります" delayMs={0} />
```
一方、UI内の演出(結果画面など)は `BloomMark` が同じ形状・配色を Web Animations API で描き直している。
**片方の形や色を変えたら、もう片方も合わせること。**

配色トークンは `src/index.css` の `@theme` にあり、すべてロゴから採色している。

| トークン | 値 | 由来 |
|---|---|---|
| `bloom-400` / `bloom-500` | `#5DCAA5` / `#3FBE93` | 花びら |
| `bloom-700` | `#0F6E56` | 花の中心。主要ボタン・正解表示に使う |
| `ink-900` | `#23292B` | ロゴのワードマーク |
| `warm-500` / `warm-600` | `#E07A5F` / `#C25A3E` | 不正解・「ちがった」の表現(緑一色の中で区別をつけるため) |

正誤は色だけに頼らず、⭕️/✖️ アイコンとテキストを併記する。

### なんいど と こたえかた

開始シートは **なんいど → こたえかた** の2ステップ。
**なんいどが先**なのは、選べるこたえかたが なんいど で変わるため
(小1・小2の漢字だけ、クイズではなく なぞり・くみたて になる)。

選べるものは [src/data/genres.ts](src/data/genres.ts) の
`difficultiesOf()` / `answerChoicesOf()` が返す。並び順がそのままシートの並びで、
こたえかたは先頭を勧める(先頭だけ色を塗る)。

| こたえかた | ジャンル | なんいど | 採点 | 出題数 |
|---|---|---|---|---|
| `handwriting` | 英単語 / 漢字 | 小3以上 | 自己申告 | 全問 |
| `typing` | 英単語のみ | 全部 | 自動 | 全問 |
| `assemble` | 漢字のみ | **小3・4 と 小5・6 だけ** | 自動 | 58問 / 41問 |
| `trace` | 漢字のみ | 小1・2 だけ | 判定なし | 240字 |
| `build` | 漢字のみ | 小1・2 だけ | 自動 | 36字 |

**`assemble` を中学以上で出さないのは、位置の表がまだ小3〜小6ぶんしか無いから。**
左右・上下のどちらに割れるかは KRADFILE に無く、手で持つしかない
(`features/assemble` の `LEFT_PART_OF` / `TOP_PART_OF`)。表に無い字を出そうとすると
**0問のセットになって「おわり」画面へ飛ぶ**ので、`ASSEMBLE_LEVELS` で出す学年を絞っている。
表を増やしたらここも広げること。

`trace` と `build` はクイズではなく別画面([/trace/kanji](src/pages/TracePage.tsx) /
[/build](src/pages/BuildPage.tsx))。こども向けの一覧からも同じ画面へ入れる。

**漢字にタイピングは置かない。** 漢字を打つには IME が要り、変換候補に答えが出てしまう。
画面内キーボードでは漢字変換を肩代わりできない。

**`typing` は OS のキーボードを使わない。** iOS の予測変換バーは
`autocomplete` / `autocorrect` / `spellcheck` では消せず、「lib」まで打つと候補に
library が並んでしまう。フォーカス可能な `input` を置かず、`OnScreenKeyboard` だけで入力する。
マウス操作の端末では畳む(判定は画面幅ではなく `(hover: hover) and (pointer: fine)`。
幅で判定すると、キーボードを持たないタブレットで入力手段が無くなる)。

**`handwriting` はなぞっている間の範囲選択を3段で止める。** 選択の青い反転が出ると、
書きかけの字と重なって書き続けられなくなる。

- キャンバスの `onMouseDown` で `preventDefault()`。`pointerdown` の `preventDefault()` では
  止まらない(マウス入力では互換マウスイベントが抑止されず、選択の開始がそのまま走る)。
  キャンバスから始まった選択は、上のヒントや残り秒数まで伸びる
- 出題語・ヒント・残り秒数の各枠に `select-none`。指がキャンバスの外へ出ても選択されない
- 書き始めに `getSelection().removeAllRanges()`。別の場所で反転したままの選択を消す

**`assemble` は部品を「思い出した」を押すまで見せない。** 先に並べると、思い出さずに
見比べて選べてしまい、再認の練習にしかならない。

**2部品を1つのマスに組ませ、置いた向きまで正誤に含める。**
下のトレイからタイルをスライド(タップでも可)して枠に入れ、2枠そろったら判定する。
`位` を `立`+`亻` と組んだら不正解。割れる向き(左右・上下)は KRADFILE に無いので、
`src/features/assemble/index.ts` の表で持つ(前述)。

マスは結果画面の**おてほんと同じ正方形+十字ガイド**にする。書いて覚える先の形と
同じ枠に組ませたいため。十字ガイドがそのまま2枠の境目になり、部品はマスの半分に入る。

**「こたえあわせ」の後に、2部品が寄って1字に組み上がる。**

```
置いたところ        押した直後          組み上がり
┌─────┐   →   ┌─────┐   →   ┌─────┐
│亻┆立│      │ 亻立 │      │  位  │
└─────┘      └─────┘      └─────┘
             寄る(300ms)    咲いて 750ms
```

組み上がりを見せるのは**押した後だけ**。置いた時点で字になると、入れ替えて試すだけで
正解が分かってしまい、思い出す練習にならない。組み上がらなかったときは離れた形へ戻し、
200ms 置いてから結果画面へ渡す(手が止まる時間を、正解のときより短くする)。

画面には正解の部品を渡さない。`PartsInput` は `assembledOf(first, second)` で
**組み上がるなら完成した字、違うなら null** だけを受け取り、演出の出し分けに使う。
答えを持たない画面のまま、組み上がりだけを描けるようにするため。

字への差し替えはヒントと同じ `animate-bloom-in`(ブラー+フェード)で、部品の層を
`opacity` で消しながら重ねる。`prefers-reduced-motion` のときは共通の指定で
動きだけが消え、組み上がった字は静止したまま同じ時間だけ出る。

寸法は**画面の高さ**で2段階に切り替える(`[@media(min-height:780px)]`)。マスもタイルも
高さが決まっていて、手書きのキャンバスと違って縮まないので、縦に短い端末では
そのままだとヒント枠へせり上がる。幅ではなく高さで切るのは、せり上がるかどうかを
決めているのが高さのため。
なお Tailwind はソースを文字列として走査するので、変種は
`` `${TALL}:size-32` `` のように組み立てず、クラス名を直接書くこと(組み立てると生成されない)。

タイルの並びは問題IDを種にした `shuffleWithSeed` で決める。描画中に `Math.random()` を
呼ぶと、再描画のたびに並びが変わって押そうとした瞬間に入れ替わる。

### 結果画面のおてほん

正解は文字列として出すだけでなく、書き写せる「おてほん」として見せる
(`src/components/ModelAnswer.tsx`)。すぐ下に「じぶんが かいた こたえ」が並ぶので、
枠の見た目と幅(`max-w-xs`・`border-bloom-200`)はそちらに揃えている。

敷くガイドはジャンル定義の `answerGuide` で決める。画面側で `genreId` を見て分岐しない。

| ガイド | ジャンル | 見え方 |
|---|---|---|
| `grid` | 漢字 | 1文字ずつマスに入れ、中心が取れるよう薄い十字ガイドを敷く |
| `baseline` | 英単語 | 英語ノートの3本線(上線・中線の点線・基線)に単語を置く |

字は本文の丸ゴシックではなく `font-display`(欧文セリフ + 明朝)で組む。
手本として写すなら、線の太さに強弱がある書体のほうが字形を追いやすい。

`baseline` の罫線は文字サイズ基準で置く必要があるため、`font-size` は外側の枠に持たせ、
罫線の位置は `em` で指定している(`px` だと文字サイズを変えたときに合わなくなる)。
基線は枠の `border-b` で描き、文字側に `-mb-[0.22em]`(行送り1の箱の descender ぶん)を
かけて基線に乗せている。これで `y` や `g` が基線の下へ出る、英語ノートと同じ見え方になる。

### 出題データの取り出しかた

出題は「全問リストを取得して画面が切り出す」形にしていない。
**1回分の出題セットを受け取り、返ってきた数がすべてとして扱う。**

```
QuizPage → useQuizSession → quizSource.startSession(genreId, inputMode) → QuizSession { questions }
                         ↘ quizSession(sessionStorage) で結果画面をはさんでも復元
```

#### 答えずに離れた問題は読み飛ばす

保存するのは出題セットと位置(`cursor`)に加えて、**その問題をもう画面に出したか**(`presented`)。
出題画面に入った時点で印を付け、次に入り直したときは印の付いた問題を飛ばして次を出す。

これが無いと、問題を見てからジャンル選択へ戻って入り直すたびに同じ問題が出る
(位置は答えたときにしか進まないため)。結果画面の「つぎの問題へ」では
`commitAdvance` が位置を進めて印を下ろすので、1問飛ばしにはならない。

**こたえかたによって出せる問題が変わる。** assemble は2部品に割れる字(`assemblyOf` が
成立する字)しか出せない。それ以外を混ぜると、選んだはずのこたえかたと違う画面が出るので、
`quizSource` が最初から配らない(セッションの保存もこたえかたごとに分けている)。

**いまは回数制限を設けていない**(そのこたえかたで出せる問題を全部シャッフルして返す)。
そのうえで、何問返すか・どの順で返すかを決めるのは
[src/services/quizSource.ts](src/services/quizSource.ts) の責務に寄せてあり、
画面はカタログの総数も未出題の残りも知らない。

要件定義書7章の「プランに応じて問題数が増える」を後から入れるときは、
`startSession` の中で切るか、同じ `QuizSource` を実装したサーバー版に差し替える。

| | いまの実装 | 制限・課金を入れた後 |
|---|---|---|
| 出題元 | バンドルした生成JSON | `fetch('/api/session')` |
| 何問返すか | そのこたえかたで出せる全問 | サーバーがプランを見て決める |
| 出題順 | シャッフル | 復習・間隔反復をサーバー側で |

差し替えるのは `quizSource` の実装1つで、`QuizSource` / `QuizSession` の形も画面側も変えない。
`statsRepository` と同じ差し替えかた。

出題数に上限を入れると、出題セットが空になりうる。その行き先は `/trial-end` に配線済み
(いまは到達しない)。`TRIAL_LIMIT` と `UserStats.trialUsed` も、
そのときに使う想定で残してある。

### バックエンド(Firebase / Supabase)

技術選定書 6章の通り採用は未確定のため、MVP では `localStorage` 実装で動かしている。
差し替え点は `src/services/statsRepository.ts` の `StatsRepository` インターフェースに閉じてあるので、
採用時は同じインターフェースの実装を足して `statsRepository` を差し替える。

### 答えの読み上げ

英単語の結果画面で答えを読み上げる(`src/services/speech.ts`)。
ブラウザ内蔵の Web Speech API を使い、外部の音声合成APIは使わない
(通信・利用料・ライセンスがどれも増えるため)。読み上げ言語は `Genre.speechLang` に持つ。

**鳴らない条件が多く、それぞれ対処が要った。** 触るときはこの4点を壊さないこと。

| 症状 | 原因 | 対処 |
|---|---|---|
| PCで無音 | Chrome は音声一覧を非同期に読む。読み込み前の `speak()` は無音になる | `voiceschanged` を待つ |
| 声がおかしい | macOS の `en-US` 一覧は先頭がネタ音声。前方一致だと Albert を掴む | 端末の既定を優先し、ネタ音声18種を除外 |
| 途中で止まる | Chrome は発話中の utterance が GC されると無音のまま止まる | モジュール側で参照を保持 |
| iOSで初回だけ鳴らない | ユーザー操作を伴わない初回の発話を弾く | 最初のタップで無音の発話を1度通す(`primeSpeech`) |

読み上げは補助機能として扱う。鳴らなくても学習の流れは止めない。
自動再生が鳴らない場合に備えて「読み方を聞く」ボタンも置いてある。

## デプロイ

Vercel を想定。`vercel.json` で SPA のフォールバックを設定済み(ビルドコマンド `npm run build`、出力 `dist`)。
