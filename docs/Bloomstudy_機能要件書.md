| No | 画面名 | 概要 |
|---|---|---|
| 1 | トップ / オンボーディング画面 | サービス紹介、ロゴアニメーション表示、開始導線 |

## 2. 機能要件

### 2.1 出題表示機能

| 項目 | 内容 |
|---|---|
| 概要 | 選択されたジャンル・出題語を画面に表示する |
| 表示内容 | 出題語のみ(答えは一切表示しない) |
| 入力 | ジャンルID、出題語ID(問題セットからランダムまたは順次選出) |
| 出力 | 出題語テキスト |

### 2.2 ヒント表示機能(ジャンル別)

| 項目 | 内容 |
|---|---|
| 概要 | 数十秒ごとにヒントを1つずつ、じわっと浮かび上がる演出とともに表示する |
| ヒント分解ルール | ジャンルごとに異なるロジックを適用する(下表参照) |
| タイマー | 出題開始からNヒント秒(初期値: 数十秒、調整可能なパラメータとする)ごとに次のヒントを開放 |
| 表示演出 | 既存プロトタイプの「ブラー+フェードイン」演出を踏襲 |
| 入力 | 出題語、ジャンルID、経過時間 |
| 出力 | 現在開放されているヒント一覧 |

**ジャンル別ヒント分解ルール(例)**

| ジャンル | 分解単位 | 例(いちご→ichigo) |
|---|---|---|
| 英語 | 英数字を1文字ずつ | i → ic → ich → ichi → ichig → ichigo |
| 漢字 | 部首・パーツ単位 | 「にんべん」→ つくりの一部 → 全体の字形 |
| その他ジャンル | ジャンル追加時に個別設計 | (今後のジャンル拡張時に定義) |

> ジャンルごとのヒント分解ルールは、ジャンル追加のたびに個別に設計・登録する前提とする(共通ロジックでは対応しない)。

### 2.3 入力モード機能

| 項目 | 内容 |
|---|---|
| 概要 | タイピング入力 / 手書き入力(キャンバス)を切り替え可能にする |
| タイピング入力 | テキストボックスへの入力を受け付ける |
| 手書き入力 | Canvas上でのペン/指入力を受け付ける。「けす」ボタンで再入力可能 |
| モード切替 | 出題画面上のトグルでいつでも切替可能(切替時に入力内容はリセット) |

### 2.4 正誤判定機能

| 項目 | 内容 |
|---|---|
| タイピング入力時 | レベル1(正規化一致)+ レベル2(編集距離によるあいまい判定)を適用 |
| 手書き入力時 | 自動判定は行わず、正解を提示した上で「できた / ちがった」の自己申告方式とする |
| 将来拡張 | フレーズ・文章ジャンル導入時にレベル4(意味的類似度判定)を追加検討(要件定義書 6章参照) |
| 出力 | 正誤結果(正解/不正解/自己申告)、正解の文字列 |

### 2.5 スコア・記録機能

| 項目 | 内容 |
|---|---|
| 概要 | 正解数、連続正解(ストリーク)を記録する |
| 記録タイミング | 各問題の正誤確定時 |
| 連続正解のリセット条件 | 不正解、または手書きモードで「ちがった」を選択した場合 |
| 表示箇所 | 出題画面上部(リアルタイム表示)、マイページ(累積・履歴) |

### 2.6 無料トライアル制御機能

| 項目 | 内容 |
|---|---|
| 概要 | 無料で解答できる問題数をカウントし、上限到達時に案内画面へ遷移する |
| カウント対象 | 出題1問ごとに1回消化(正誤に関わらず解答完了時点でカウント) |
| 上限到達時の挙動 | 無料トライアル終了案内画面へ遷移する。サブスク導線の具体的な仕様は次フェーズで別途定義する |

## 3. 非機能要件

| 項目 | 内容 |
|---|---|
| デバイス対応 | スマートフォンでの利用を最優先(レスポンシブ対応必須)。タブレット・PCでも表示崩れがないこと |
| パフォーマンス | 意味的類似度判定(レベル4)導入時、初回モデル読み込みに数秒〜十数秒かかることをユーザーに明示する(ローディング表示) |
| アクセシビリティ | 子どもから大人まで利用するため、文字サイズ・タップ領域を十分に確保する。色のみに依存しない正誤表現(色+アイコン/テキスト)とする |
| 対応ブラウザ | 主要モダンブラウザ(Chrome, Safari, Firefox の最新版)を対象とする |
| オフライン対応 | MVP時点では非対応(将来のPWA化検討時に再考) |

---

## 4. 今回のスコープ外(次フェーズ以降で検討)

- サブスクプランの価格・区分の詳細仕様(要件定義書 7章の方針の通り)
- 手書き入力のOCRによる自動判定
- ジャンル拡張時の追加ヒントルール設計(ジャンルごとに都度設計)
- 文法チェックAPI(レベル3)の導入可否
