# Bloomstudy 要件定義書

**作成日**: 2026年8月21日
**ステータス**: 初期構想 / プロトタイプ検証段階

---

## 1. サービス概要

ゲーム型の学習ウェブアプリケーション。出題された単語・言葉に対して、数十秒ごとに段階的なヒントが浮かび上がる形式で解答を「思い出す」体験を提供する。回答方法はタイピング入力と手書き入力の両方に対応する。

- サービス名(仮): **Bloomstudy**
- 対象年齢層: 子どもから大人まで
- 提供形態: ウェブアプリ(スマートフォン対応)

---

## 2. 背景・課題認識

- デバイスの普及により「調べればすぐ答えが出る」「書かなくても済む」時代になっている
- 一方で、実生活では自力で思い出す力・自分の手で書く力が必要になる場面は残っている
- このギャップを埋め、日常で役立つ「思い出す力」「書く力」を鍛える教育サービスとして位置づける
- 将来的には、本サービスをきっかけにゼミ・塾など対面学習への興味喚起の入口としても機能させたい

---

## 3. コンセプト・差別化ポイント

### 3.1 答えを出さない出題形式
既存のタイピング練習系サービス(寿司打など)は、最初から正解の文字列が画面に表示されている「変換作業」に近い。本サービスは**出題語(例:いちご)のみを表示し、答え自体は最初から見せない**。これにより、単なる反復練習ではなく検索練習(retrieval practice)、すなわち「思い出そうとする行為」自体を学習の core に据える。

### 3.2 段階的ヒント表示(ジャンルごとに出し方を変える)
- 数十秒ごとにヒントが1つずつ、じわっと浮かび上がるように表示される
- ヒントの出し方はジャンルの特性に合わせて設計する。汎用的な「文字数・頭文字」ではなく、**そのジャンルらしい単位でヒントを分解して出す**ことを基本方針とする
  - 例: 英語 → 英数字を1文字ずつ出していく(i → ic → ich …)
  - 例: 漢字 → 部首・パーツ単位で出していく(例:「にんべん」→「つくり」の一部 → 全体)
  - 他ジャンルについても、それぞれの構成要素に応じたヒント分解単位を今後設計する
- ヒントが出るまでの「考える時間」自体が学習効果の中心

### 3.3 手書き入力への対応
- タイピングに加え、指(またはペン)で直接書く手書き入力モードを用意
- 手書きは想起・記憶定着の観点でタイピングより優位という研究知見(例: Mueller & Oppenheimer)を踏まえた設計
- 手書きモードは厳密な自動判定が難しいため、自己採点方式(答えを見て「できた/ちがった」を選ぶ)を基本とする

### 3.4 入力方法を問わない体験設計
ブランド上のシンボルは「花が開くように答えが浮かび上がる」イメージ(Bloomstudy)とし、手書き・タイピングいずれの入力方法にも偏らない中立的な世界観とする。

## 4. ターゲットユーザー

- 小さな子どもから大人まで、幅広い年齢層
- 語学学習・雑学・専門用語など、複数ジャンルに関心を持つ学習者
- 将来的にゼミ・塾など対面学習に興味を持つ可能性のある層

---

## 5. 主な機能(構想)

| 機能 | 内容 |
|---|---|
| 出題表示 | 出題語のみを画面に表示し、答えは表示しない |
| 段階的ヒント | 数十秒ごとにヒントが1つずつ浮かび上がる。ヒント消費数に応じたスコア減点なども検討 |
| 入力モード切替 | タイピング入力 / 手書き入力(キャンバス)を切り替え可能 |
| 正誤判定 | タイピングは文字列判定、手書きは自己採点方式(詳細は6章) |
| ジャンル選択 | 英単語に限らず、漢字・雑学・専門用語など複数ジャンルを展開予定 |
| スコア・連続正解 | 正解数・連続正解(ストリーク)を記録し、継続動機を高める |
| 無料お試し | 数回分は無料で利用可能 |
| サブスクプラン | プランに応じてジャンル数・問題数が拡張される課金モデル |

## 6. 正誤判定方式の検討

出題内容の難易度(単語 / 短いフレーズ / 文章)に応じて、判定方式の選択肢を整理する。

| レベル | 方式 | 概要 | コスト | 主な用途 |
|---|---|---|---|---|
| 1 | 完全一致・正規化一致 | 大文字小文字統一、余分な空白除去等をした上で文字列比較 | 無料・実装容易 | 単語 |
| 2 | 編集距離(レーベンシュタイン距離) | タイプミス程度の誤差を許容するあいまい判定 | 無料・軽量ライブラリで実装可 | 単語・短いフレーズ |
| 3 | 文法チェックAPI(LanguageTool等) | 文法的な正しさをチェック。内容の正誤判定とは別軸 | 無料枠あり(呼び出し制限あり) | 文章の文法チェック補助 |
| 4 | 意味的類似度判定(埋め込み/エンベディング) | 文章をベクトル化し、コサイン類似度で意味の近さを判定。語順や言い回しの違いに強い | 無料(ブラウザ内完結、Transformers.js等) | フレーズ・文章 |

**現時点の方針**
- 単語・短いフレーズ: レベル1+レベル2の組み合わせで十分実用的、優先実装
- 文章対応(将来拡張): レベル4(意味的類似度判定)を軸に検討。文法的な誤りまで検知したい場合はレベル3と組み合わせる
- レベル4はブラウザ内(Transformers.js, all-MiniLM-L6-v2等)で完結させることで、サーバーコスト・API利用料なしで実現可能。ただし初回モデル読み込みに数秒〜十数秒かかる点は考慮が必要

## 7. ビジネスモデル

- 無料お試し(数回分)を提供し、その後はサブスクリプション課金へ移行する構想
- プランに応じてジャンル数・問題数が増加する段階的な料金設計を想定
- アプリ単体でのマネタイズに加え、**対面学習(ゼミ・塾)への導線**としての役割も持たせ、長期的な関係構築を目指す

> **検討時期について**: サブスクの価格帯・プラン区分などの具体的な設計は、実際にサービスとして売り出す段階になってから検討するものとし、現時点(構想・プロトタイプ検証段階)では詳細を詰めない。

## 8. ブランド・ロゴ

- サービス名: **Bloomstudy**
- コンセプト: 花びらが開くように、記憶がふわっと呼び起こされるイメージ
- 選定理由:
  - 「答えが浮かび上がる」という体験の核心と一致
  - 手書き・タイピングいずれの入力方法にも偏らない中立的なメタファー
  - 子どもにも親しみやすく、大人にも柔らかい印象を与えられる
- ロゴ仕様:
  - 5枚の花びらが順番に開き、続けてロゴ文字がフェードインするアニメーションを基本仕様とする
  - 縦組み(アイコン+ロゴが縦並び)・横組み(アイコン+ロゴが横並び)の2バリエーションを用意
  - アニメーション版は起動画面・ローディング演出・正解時のフィードバック演出への転用を想定
