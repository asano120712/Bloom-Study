# Bloomstudy 技術選定書

**作成日**: 2026年8月22日
**対象フェーズ**: MVP構築(無料トライアルまでの範囲。サブスク決済まわりは対象外)

---

## 1. 選定方針

- 個人〜小規模チームでのMVP開発を前提とし、**初期コストの低さ・実装速度**を優先する
- 判定ロジックはできる限りブラウザ内で完結させ、サーバーコストとレイテンシを抑える
- 将来のサブスク課金・ジャンル拡張を見据え、拡張しやすい構成にしておく
- スマートフォンでの利用を主軸とし、レスポンシブ対応を前提に設計する

---

## 2. 技術スタック一覧

| レイヤー | 選定候補 | 推奨 | 理由 |
|---|---|---|---|
| フロントエンド フレームワーク | React / Vue / Vanilla JS | **React(TypeScript)** | コンポーネント単位でジャンルごとのヒントロジックを切り替えやすい。エコシステムが大きく、後述のライブラリとの相性も良い |
| スタイリング | CSS Modules / Tailwind CSS | **Tailwind CSS** | スマホ優先のレスポンシブ調整がしやすく、プロトタイプで作った世界観(花びらモチーフ等)をユーティリティベースで素早く再現できる |
| 手書き入力 | HTML Canvas API | **Canvas API(素のまま)** | 外部ライブラリなしで実装可能。プロトタイプで動作確認済み |
| タイピング判定(レベル1・2) | 正規表現 + `fast-levenshtein` | **採用** | 無料・軽量、単語〜短いフレーズの判定に十分な精度 |
| 意味的類似度判定(レベル4) | Transformers.js(`Xenova/all-MiniLM-L6-v2`) | **採用(将来のフレーズ・文章対応時)** | ブラウザ内完結、API利用料なし。プロトタイプで動作確認済み |
| アニメーション | CSS Animations / Web Animations API / SVG SMIL | **Web Animations API(UI内)+ SVG SMIL(ロゴ単体アセット)** | UI内の演出はJSから制御しやすいWeb Animations API、ロゴ単体ファイルとして配布する場合は自己完結型のSMILが便利。用途で使い分ける |
| バックエンド(認証・データ保存) | Firebase / Supabase / 自前API | **Firebase(Authentication + Firestore)または Supabase** | ユーザー管理・スコア保存・無料トライアル回数のカウントなどをサーバーレスで構築でき、MVP段階のインフラコストを抑えられる。両者は機能的に近く、SQLで扱いたい場合はSupabase、ドキュメント指向で手早く始めたい場合はFirebaseが目安 |
| ホスティング | Vercel / Netlify / Firebase Hosting | **Vercel(または選定したBaaSに合わせてFirebase Hosting)** | 個人開発・小規模チームでのデプロイが容易 |
| フォント | Google Fonts | **採用** | 無料で商用利用可能。ロゴ・UIで使用しているフォントもここから調達 |

## 3. 判定ロジックの実装方針(技術選定書としての補足)

要件定義書 6章の判定レベルに対応する技術選定は以下の通り。

| レベル | 使用技術 | 実装フェーズ |
|---|---|---|
| レベル1(正規化一致) | JavaScript標準機能(`toLowerCase()`, `trim()`, 正規表現) | MVP初期から実装 |
| レベル2(編集距離) | `fast-levenshtein`(npm) | MVP初期から実装 |
| レベル3(文法チェック) | LanguageTool 公開API | 将来検討(無料枠の呼び出し制限に留意) |
| レベル4(意味的類似度) | Transformers.js + `all-MiniLM-L6-v2` | フレーズ・文章ジャンル対応時に導入 |

サブスク設計自体は次フェーズの検討事項だが、実装時の技術候補として参考までに記載する。
